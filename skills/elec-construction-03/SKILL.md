# 电气施工设计与强条自检（elec-construction-03）

## 0. 目标、边界与红线

角色：电气施工设计工程师。

目标：在阶段2 IO/BOM 基础上完成阶段3电气施工配套设计，输出：

1. `./output/03-electrical/io_address.xlsx`：分配完成物理地址的IO表；
2. `./output/03-electrical/loop_description.md`：回路说明文档；
3. `./output/03-electrical/cable_schedule.xlsx`：电缆表及计算证据；
4. `./output/03-electrical/terminal_list.xlsx`：端子表；
5. `./output/03-electrical/clause_check.xlsx`：强条自检表；
6. `./output/03-electrical/drawing_data.json`：全项目统一数据源；
7. `./output/03-electrical/plc_tag_map.csv`、`./output/03-electrical/plc_tag_table.xml`：PLC 变量表映射与导入文件（过程产物，CSV 供追溯、XML 供阶段4 导入；不计入阶段3 的 6 项交付物门槛，但缺失会阻断阶段4）。

本技能只做阶段3：地址分配、回路描述、电缆/端子表、强条技术预检、统一数据源。**不输出**EPLAN/CAD图纸、图面布局、接线图、PLC程序、HMI画面。

始终遵守以下红线：

1. **一线一端子**：每个端子位只允许一根导线；禁止同一端子压接两根不同回路导线。多根导线需要共电位时，用桥接件连接**不同端子**，不得把多根线塞进同一端子。
2. **每排端子≥15%备用**：X1/X2/X3/X4 每一排按“使用端子+备用端子”计算，备用比例≥15%；备用端子集中在排尾。
3. **JSON唯一数据源**：`drawing_data.json` 是唯一权威源；所有xlsx/md从JSON导出，并带数据版本/JSON指纹。禁止只改表格不改JSON。
4. **不编造**：不编造条款号、标准号、条款原文、设计证据、器件型号、电缆参数、短路电流、保护动作时间。缺数据就标 `待补`/`待人工判定` 或阻塞。
5. **不越界**：不画图、不做图面布局、不写PLC/HMI程序、不做施工图深化。
6. **真实文件**：xlsx 用 `python3` + `openpyxl` 生成；禁止CSV改扩展名。

**快速导航**：1 输入输出｜2 总流程｜3 地址分配｜4 回路说明｜5 电缆计算｜6 端子表｜7 强条自检｜8 JSON｜9 一致性与整改｜10 交付自检｜11 对话契约｜附录

## 2. 总流程（JSON先行）

```text
读入/验字段
  → 建统一模型（需求/IO/BOM/地址/回路/电缆/端子/条款）
  → 地址分配（ADDR-V）
  → 回路划分（W）
  → 电缆计算与判定
  → 端子表与一线一端子/15%校验
  → 强条适用性/证据/初判
  → 确定性整改与重算（最多5轮）
  → 写 drawing_data.json（DATA-V）
  → 从JSON导出5个附属文件
  → 校验导出与JSON一致（哈希/计数/ID）
  → 交付（待工程师审阅）
```

关键原则：

- **先模型、后JSON、再导出**。首次可以从阶段2文件导入，但定稿后所有xlsx/md必须从JSON重放；禁止“表格改了、JSON没改”。
- 地址、电缆、端子、强条互相引用；任一处变更必须更新JSON、升版、重导出、重校验。
- 计算和判定用脚本；文字说明可以用LLM整理，但数字/ID/证据必须来自脚本和JSON。

### 2.1 两遍/迭代

- 地址分配先做，回路/电缆/端子依赖地址；电缆计算可能因压降/载流/热稳定不通过而改截面/路径，进而影响端子/版本；强条整改可能反过来改回路/电缆/BOM。
- 因此允许**最多5轮**“改模型→重算→重导出”；每轮写`remediation_log`。超过5轮仍不收敛，停止并报告。

## 3. IO物理地址分配（io_address.xlsx）

### 3.1 地址映射profile

物理地址不能靠品牌猜测。按以下顺序解析：

1. 用户提供 `address_profile.json`/`address_profile.xlsx`：使用其地址布局。
2. 未提供时，若BOM中CPU型号可识别为 **S7-1200系列**，可用内置默认profile（仅作初版，最终以硬件组态为准）：

```json
{
  "profile_id": "S7-1200-DEFAULT",
  "cpu_family": "S7-1200",
  "di_start": "I0.0",
  "do_start": "Q0.0",
  "ai_start": "IW64",
  "ao_start": "QW80",
  "m_bit_start": "M0.0",
  "mw_start": "MW100",
  "expansion_di_start": "I8.0",
  "expansion_do_start": "Q8.0",
  "analog_step_bytes": 2,
  "note": "起始地址模板；扩展模块顺序/字节按BOM顺序假设，最终以硬件组态为准"
}
```

3. CPU型号不识别、或缺集成/扩展通道数、或不是S7-1200且无profile：停止地址分配，返回：

```text
【缺少地址映射：CPU型号/模块通道/起始地址】
```

不要用“常见地址”跨品牌套用。

### 3.2 分组规则

- 功能组键：`设备标签` 第一个 `_` 之前的前缀；没有前缀用 `关联REQ-ID`；仍无则用 `信号名` 的段前缀。不要用随机ID分组。
- 组顺序：按组内最小 `IO-ID` 升序（继承阶段2的功能顺序）。
- 组内顺序：按 `设备标签`、再按 `IO-ID`；同一设备的信号尽量相邻。
- 物理IO只处理 `DI/DO/AI/AO` 且 `备用标志=使用`；`备用` 另列；`内部`/`HMI` 单独处理。
- 同一信号不得重复分配；`IO-ID` 必须唯一。

### 3.3 分配规则

| 类型 | 区域 | 分配 |
|---|---|---|
| DI | CPU本体/扩展DI | 按功能组连续分配；同一设备相邻；同一地址块内连续、不跳空；跨CPU/扩展块按profile跳转 |
| DO | CPU本体/扩展DO | 同上 |
| AI | 固定过程映像区 | 按功能组/设备分配；每通道2字节，起始地址用profile |
| AO | 固定过程映像区 | 同上 |
| 内部 | M位/MW字 | 开关/状态/报警用M位；数值/计数/设定用MW；不得与I/Q重叠 |
| HMI | 无物理通道 | `物理地址=—`，地址区`HMI`；若映射内部M/MW，写映射地址 |

补充规则：

- 数字量按位分配：字节.位，位0–7；跨字节连续；不得重复。
- 模拟量按字分配：每通道2字节；地址必须是profile允许的字地址；不得与数字I/Q重叠。
- **备用通道集中放置每组通道末尾**：这里的“每组”按 `DI/DO/AI/AO` 类型组理解；每种类型先排使用点，再排该类型备用点；备用点不得穿插在功能组之间，也不得插在使用地址中间。
- CPU本体通道用完后，按profile进入扩展块；扩展模块按BOM顺序/字节步长分配；如果模块通道数与地址块不匹配，停止，不猜。
- 内部M位与MW字分开分配：M位从`M0.0`起，MW从`MW100`起；不得重叠。若CPU M区容量不足，停止/报告。
- 内部标签判定：`电压电流规格`含`WORD/INT/REAL/MW`，或信号名明确为数值/设定/计数/速度/温度/时间/配方 → MW字；其余状态/报警/标志 → M位。无法判定时按M位分配并报告“宽度待确认”，不得猜MW。
- HMI标签不占PLC硬件通道；不分配I/Q。

### 3.4 地址表字段

`io_address.xlsx` 主表固定字段（16列）；另设`00-说明与版本`记录`DATA-V`、`ADDR-V`、JSON SHA256、地址profile、生成时间：

```text
IO-ID | 信号名 | PLC符号 | 类型 | 物理地址 | 方向 | 地址区 | 字节位 | 设备标签 | 备用标志 | NC语义 | 关联REQ-ID | 回路号 | 关联BOM-ID | 地址版本 | 备注
```

取值：

| 字段 | 规则 |
|---|---|
| IO-ID | 继承阶段2；不重号 |
| 信号名 | 继承；可加“（地址分配）”说明不加列 |
| PLC符号 | 写入PLC变量表的符号名：ASCII，仅字母数字下划线，不以数字开头；工程内唯一；由本阶段统一生成，阶段4 直接引用，禁止改名 |
| 类型 | DI/DO/AI/AO/内部/HMI |
| 物理地址 | `I0.0`/`Q0.0`/`IW64`/`QW80`/`M0.0`/`MW100`；HMI为`—` |
| 方向 | `DI`/`DO`/`AI`/`AO`/`内部`/`HMI`；与类型一致，供阶段4 判断可写性 |
| 地址区 | `本体DI`/`扩展DI`/`本体DO`/`扩展DO`/`AI过程映像`/`AO过程映像`/`M位`/`MW字`/`HMI` |
| 字节位 | 数字量`字节.位`；模拟量字地址；内部/HMI同物理地址或`—` |
| 设备标签 | 继承 |
| 备用标志 | `使用`/`备用`/`—` |
| NC语义 | 仅使用中的开关量必填：`NO`（TRUE=动作）/`NC`（FALSE=正常）；备用点未指定用途、模拟量、内部/HMI 写`—`；缺失即缺陷（阶段4 取反、阶段5 构造激励都依赖本列） |
| 关联REQ-ID | 继承；备用可为`SYSTEM` |
| 回路号 | W1/W2…；备用`—` |
| 关联BOM-ID | 对应现场器件/模块；无则`—` |
| 地址版本 | `ADDR-V…` |
| 备注 | 默认profile/假设/映射说明 |

### 3.5 版本与变更

- 首次生成 `ADDR-V1.0`。
- 任一物理地址变化：minor+1（如V1.1）；地址布局/CPU/模块拓扑变化：major+1（V2.0）。
- 变更必须写入 `version_log`：时间、旧版/新版、原因、受影响IO-ID、操作者。
- 地址变化后，端子表`对接端子`中的`PLC:地址`、电缆/回路的地址引用、JSON追溯全部更新并重导出。
- 保留旧版地址表或至少保留版本记录；不得静默覆盖无版本。

### 3.6 地址校验

- 每个使用中物理IO都有且仅有一个地址；备用点有地址且集中在类型末尾。
- 无重复、无重叠、类型/区域匹配、位0–7合法、模拟量字地址符合profile。
- 同一功能组的数字地址在同一地址块内连续（允许跨字节）；跨CPU/扩展块按profile；同一设备信号相邻（除非BOM无设备标签，报告例外）。
- 所有地址在profile允许范围；扩展模块通道数/序号不越界。
- 内部M位/MW字不重叠；HMI不占I/Q。
- 地址版本存在；变更日志完整。

### 3.8 PLC 变量表映射（plc_tag_map.csv / plc_tag_table.xml）

地址表定稿后，必须同步导出两份文件：

- `./output/03-electrical/plc_tag_map.csv`（UTF-8 BOM、逗号分隔）：全量映射，含 HMI 与备用行，供追溯与人工核对；
- `./output/03-electrical/plc_tag_table.xml`（UTF-8 BOM）：仅 PLC 变量（DI/DO/AI/AO/内部），排除 HMI；供阶段4 `ImportPlcTagTable` 直接导入。

CSV 列固定：

```text
IO-ID,Symbol,Address,DataType,Direction,NcSemantic,REQ-ID
IO-001,SB1_ESTOP_NC,I0.0,Bool,DI,NC,REQ-001
IO-002,SEG01_M1_RUN,Q0.0,Bool,DO,NO,REQ-002
IO-003,TT101_AI,IW64,Int,AI,—,REQ-003
```

规则：

1. `plc_tag_map.csv` 行数 = `io_address.xlsx` 主表行数（含备用行与 HMI；备用行 `REQ-ID=SYSTEM`，HMI 行 `REQ-ID` 按需求）。
2. `Symbol` 与地址表 `PLC符号` 逐字一致，工程内唯一，阶段4 不得改名校验。
3. `DataType` 按类型确定，不得按“模拟量”三个字猜：
   - DI/DO、内部 M 位：`Bool`；
   - AI/AO、内部 MW 字：`Int`/`Real`/`Word`，取接口契约或模块通道类型；
   - HMI：`—`（不进入 PLC 变量表；如需 HMI 标签表，另出清单，不在本文件导入）。
4. `plc_tag_table.xml` 由 CSV 生成，标签数 = CSV 行数 − HMI 行数；`name`=`Symbol`、`logicalAddress`=`Address`、`dataTypeName`=`DataType`。生成方式：调用 `BuildPlcTagTableXml`（输入 `{tableName,tags:[...]}`，表名由契约/用户指定，默认 `PLC_Tags`），或使用等价本地转换器；禁止手写 XML。
5. `plc_tag_table.xml` 与 CSV/地址表不一致，或缺失、含 `DataType=TBD` → 阶段4 按 `E07_*` 阻断（见 `plc-scl-gen-04` §2.2）。

## 4. loop_description.md 回路说明

### 4.1 回路划分

按现场施工习惯划分独立回路 `W1/W2…`：

- `W1`：24V控制电源/系统回路（CPU、模块、电源、HMI供电等）。
- 动力回路：每台电机/驱动/大功率执行器单独回路。
- 控制/信号回路：同一保护器件、同一电缆路径、同一功能组的传感器/按钮可合并；不共享保护/路径则拆分。
- 安全回路：每个安全功能（急停、安全门、安全继电器）独立回路；示例W3急停安全回路。
- 指示/报警回路：按功能/保护分组。

回路编号直接作为电缆编号前缀：`W3` → `W3-C01`、`W3-C02`。

映射阶段2 `CIR-*`：

| 阶段2回路 | 阶段3回路 |
|---|---|
| `CIR-SYS`、`CIR-PWR-24V` | `W1` |
| `CIR-SAFE-*` | 安全回路（W编号按顺序；可W3等） |
| `CIR-SEG-*` | 对应功能回路 |
| 无/空 | 按BOM设备类别/IO分组；报告映射假设 |

### 4.2 每条回路必须写

0. 文档头：项目、`DATA-V`、`ADDR-V`、JSON SHA256、生成时间；
1. 回路编号、名称、类型（动力/控制/安全/电源/信号/指示）；
2. 功能说明；
3. 器件清单（BOM-ID、名称、型号、数量）；
4. 保护器件型号（断路器/熔断器/电机保护/安全继电器；无则`待确认`）；
5. 导线规格（电缆ID、型号、芯数×截面、长度）；
6. 关联REQ-ID、IO-ID、端子排；
7. 电缆计算摘要（电流/载流量/压降/热稳定/综合判定）；
8. 安全/联锁说明（如适用）；
9. 备注/待确认项。

### 4.3 保护器件与导线

- 保护器件必须来自BOM/库内；不得编型号/额定值。BOM没有保护器件时写`待确认`，并列入缺项；不得默认“有断路器”。
- 导线规格来自 `cable_schedule.xlsx`；不得在回路说明里另写一套截面/长度。
- 安全回路必须写清双通道/单通道、急停范围、复位方式（仅限BOM/REQ已有信息；不自行设计）。
- 回路说明只写文字/表格，不写端子排布图、接线图、图面布局。

### 4.4 示例结构

```markdown
## W3 急停安全回路

- 回路类型：安全
- 功能：急停按钮触发后，经双通道安全继电器切断相关执行输出；复位方式按REQ。
- 关联REQ：REQ-SAF-...
- 关联CIR：CIR-SAFE-ESTOP
- 器件清单：BOM-010 急停按钮；BOM-011 双通道安全继电器；BOM-012 熔断器
- 保护器件：BOM-012 <型号>（库内）
- 导线规格：W3-C01 <型号> 4×1.0 mm²，长度<...>m
- 关联IO：IO-001、IO-002
- 计算摘要：载流通过；压降≤5%；热稳定<适用/不适用>
- 端子：X4-01～X4-06
- 备注：安全等级/复位方式待工程师确认
```

## 5. 电缆表与计算（cable_schedule.xlsx）

### 5.1 输出结构

`cable_schedule.xlsx` 至少包含：

- `00-说明与版本`：数据版本、JSON指纹、计算依据、参数来源、边界；
- `01-电缆计算`：每条电缆一行，输入+结果+判定；
- `02-计算依据`：每条电缆的R20/X/运行温度/Rθ/修正系数/k/公式/数据来源。

主表字段（至少）：

```text
CABLE-ID | 回路号 | 回路类型 | 起点 | 终点 | 电缆型号 | 芯数 | 截面(mm²) | 长度(m) |
电压(V) | 相数 | 负载类型 | 负载功率(kW) | cosφ | η | 负载电流(A) |
计算电流(A) | 载流量表值(A) | 修正后载流量(A) | 载流判定 |
压降(V) | 压降(%) | 压降判定 | 短路电流(A) | 保护动作时间(s) |
热稳定最小截面(mm²) | 热稳定判定 | 综合判定 |
关联IO-ID | 关联BOM-ID | 数据版本 | 备注
```

`02-计算依据` 字段：

```text
CABLE-ID | R20(Ω/km) | X(Ω/km) | 运行温度(°C) | Rθ(Ω/km) |
温度修正 | 成组修正 | 敷设修正 | 热稳定系数k | 计算公式 | 数据来源
```

### 5.2 输入与数据来源

每条电缆录入：

- 起点、终点（设备标签/端子，不画图）；
- 电缆型号、芯数、截面、长度；
- 电压、相数（1/3/DC）、负载类型（电机/电阻/控制/其他）；
- 负载功率、cosφ、η；控制回路可用负载电流代替功率；
- 载流量表值、R20、X、k、绝缘/导体、敷设/温度/成组修正；
- 短路电流、保护动作时间（动力回路）。

数据来源：

- 电缆参数优先来自 `cable_library.xlsx` 或厂家数据；不得用“常用值”伪装厂家值。
- 负载功率/电流来自BOM/需求/电机铭牌；缺就 `待补`，不猜。
- cosφ/η来自电机铭牌/需求；缺就 `无法判定`，不默认0.8/0.85。
- 短路电流/保护动作时间来自短路计算/保护整定；缺就 `待人工判定`，不得用电缆回路理论值冒充。
- 载流量表值必须与型号/芯数/截面/敷设对应；不对应就 `待补`。

**模拟模式（仅 `auto_simulate_customer=true`）**：上表的 `待补` / `无法判定` / `待人工判定` 允许由模拟电气工程师给出**保守取值**后继续计算，但：

1. 每一项模拟取值必须在对应行标记 `【模拟裁决】`，并写清：缺什么、取什么值、依据、需如何实测复核；
2. 取值方向必须保守（载流量取下限、cosφ/η 取下限、长度取偏大、短路电流取偏小），**不得取有利于“通过”的值**；
3. 模拟只影响计算用的输入，不得改写 `io_list`/`bom` 里的原始参数；
4. 全部模拟项必须进入 `drawing_data.json` 的 `open_items` 与最终报告“待复核”栏。

### 5.3 计算电流

`P` 用W（表中kW先×1000），`U` 用V：

| 负载 | 公式 |
|---|---|
| 三相电机 | `I = P / (√3 × U × cosφ × η)` |
| 单相电机 | `I = P / (U × cosφ × η)` |
| DC电机 | `I = P / (U × η)` |
| 电阻/控制负载 | `I = P / U`；或直接用给定负载电流 |
| 24V控制 | `I = P / 24`；或直接用给定电流 |

控制/电阻负载取`cosφ=1`、`η=1`；24V控制按DC公式。校验：`P>0`、`U>0`、`0<cosφ≤1`、`0<η≤1`；否则 `无法判定`，不得强行算。

### 5.4 载流量

```text
Iz = Itable × Kt × Kg × Ki
```

- `Itable`：所选电缆在标准敷设下的载流量；缺 `Itable` → `待补数据`，不得用经验值冒充。
- **模拟模式例外**：`auto_simulate_customer=true` 且无 `cable_library.xlsx` 时，允许按 `Itable = 截面(mm²) × 3 A/mm²`（铜芯、空气中敷设、30℃、取下限）估算，标 `【模拟裁决】`；修正系数 `Kt/Kg/Ki` 一律按 `1.0` 并备注“未修正-需复核”。该估算值不得写成厂家数据，也不得在报告中出现“满足载流量要求（已核实）”。
- `Kt` 温度修正、`Kg` 成组修正、`Ki` 敷设修正；
- 未提供修正系数时，按`1.0`并用备注“标准敷设未修正”；现场条件不同必须复核。
- 判定：`Iz > I`（严格大于）；等于不通过。
- `Itable`/截面/型号不匹配时 `无法判定`。

### 5.5 电压降

`L` 用km，`Rθ/X` 用Ω/km：

| 回路 | 公式 |
|---|---|
| 三相 | `ΔU = √3 × I × L × (Rθ×cosφ + X×sinφ)` |
| 单相 | `ΔU = 2 × I × L × (Rθ×cosφ + X×sinφ)` |
| DC/24V | `ΔU = 2 × I × L × Rθ` |

`ΔU% = ΔU / U ×100`；判定 `ΔU% ≤5.00%`。

`Rθ`：

```text
Rθ = R20 × (1 + α × (θ - 20))
```

- 铜 `α=0.00393/°C`；铝 `α=0.00403/°C`；
- `R20` 优先用电缆数据；没有时可按下式计算并注明“计算值”：`R20 = ρ20 × 1000 / S`（Ω/km），铜 `ρ20=0.0175 Ω·mm²/m`、铝 `ρ20=0.0283 Ω·mm²/m`；
- `θ` 优先用绝缘允许温度；PVC默认70°C、XLPE默认90°C；绝缘不明时用70°C并注明假设；
- `X` 优先用电缆数据；`S≤16mm²`且无数据时可按0并注明“未计电抗”；`S>16mm²`无X数据时 `无法判定`。

### 5.6 短路热稳定

仅动力回路强制；控制/信号可标 `不适用`。

```text
S_min = Isc × √t / k
```

- `Isc`：电缆起点预期短路电流（A），来自短路计算/保护数据；
- `t`：保护动作时间（s），来自保护整定；
- `k`：热稳定系数，按导体/绝缘取；常用参考：铜PVC 115、铜XLPE 143、铝PVC 76、铝XLPE 94；以项目标准/厂家数据为准；
- 判定：`S ≥ S_min`。
- `Isc`/`t`/`k` 任一缺失：`待人工判定`，不得用假设值冒充。
- 若 `t` 过长或超出 adiabatic 假定，报告“需按标准曲线复核”。

### 5.7 判定与综合

| 判定 | 规则 |
|---|---|
| 载流 | `Iz > I` |
| 压降 | `ΔU% ≤5.00%`（动力+24V控制；信号同限或项目更严） |
| 热稳定 | 动力：`S ≥ S_min`；非动力：`不适用` |
| 综合 | 任一适用项不通过→`不通过`；无失败但有未知→`待人工判定`；全通过/不适用→`通过` |

- 判定用未舍入值，显示2位小数；避免5.004%显示5.00%被误判。
- 每条电缆保留全部输入/结果/公式/数据来源，不能只写“通过”。

### 5.8 脚本要求

- 脚本读取电缆行→计算公式→回填表/JSON；重复运行结果一致。
- 不得修改输入值来“凑通过”；整改必须记录改动前后。
- 任何 `不通过` 触发整改循环：增大截面、缩短路径、换库内电缆型号、增加并联回路、调整保护；重算后再判定。
- 不得用库外电缆型号或编造载流量。

## 6. 端子表（terminal_list.xlsx）

### 6.1 固定字段（10列，顺序固定）

```text
TERM-ID | 端子排 | 端子号 | 线号 | IO-ID | 回路号 | 信号名称 | 导线截面 | 颜色 | 对接端子
```

- 只允许这10列。`IO-ID`/`回路号` 是阶段5 构建 IO→TERM 追溯链的唯一依据，**不得省略、不得留空**（备用行填`—`，但连接类端子必须填）；信号名称仅供人读，不作为关联键。
- 主表`01-端子表`；另设`00-说明与版本`、`02-备用统计`。
- 第1行表头；第2行起数据；无标题行、无合并单元格。
- `00-说明与版本`记录`DATA-V`、`ADDR-V`、JSON SHA256、生成时间。

### 6.2 端子排

| 端子排 | 用途 |
|---|---|
| `X1` | 电源：24V+、0V、PE；动力电源按项目 |
| `X2` | 输入：非安全DI/AI |
| `X3` | 输出：非安全DO/AO |
| `X4` | 安全：急停、安全门、安全继电器、安全输出 |

- 安全信号优先放X4，不放X2/X3。
- 端子号两位连续：`X1-01`、`X1-02`…；备用在排尾。
- `TERM-ID`与`端子号`对应：`X1` + `-` + `01`；`端子排`=`X1`；`端子号`=`01`。

### 6.3 一线一端子模型

本表按“端子位”建模，每个端子位只接一根导线：

- 每个 `TERM-ID` 只出现一行；该行只有一个 `线号`（备用行写`备用`）。
- 一根线最多出现两次（两端都在端子排时）；两次的 `对接端子` 必须互相指向。
- 一端是设备/PLC端子时，只出现一次；`对接端子` 用 `DEV:<设备标签>:<端子>` 或 `PLC:<物理地址>`。
- 两端都是端子排时，`对接端子` 用 `TERM:<TERM-ID>`。
- 共电位/桥接：用 `BRIDGE:<TERM-ID>` 连接不同端子；桥接件不算导线，不得把两根线压进同一端子。
- 禁止同一个端子压接两根不同回路导线：本模型一个端子一行一根线；再加 `线号` 回路前缀校验。

`线号`规则：`W<n>-<两位序号>`，如`W3-01`；同一根线两端同号；不同线不得重号。`线号`前缀必须与所属回路一致。

### 6.4 15%备用

按每个端子排分别计算：

```text
used = 非备用端子数（线号≠备用）
spare_min = ceil(used / 0.85) - used
total = used + spare
spare_ratio = spare / total
```

要求 `spare_ratio ≥15%`；备用端子放在该排末尾。每个有用端子的排都要满足；空排可不建。

### 6.5 截面/颜色

- `导线截面`：来自电缆表/回路；同一线号的截面必须与电缆表一致；备用写`—`。
- `颜色`按项目/常规：
  - 24V+ 红；0V 蓝/黑；PE 黄绿；
  - AC L 棕/黑；N 蓝；
  - 安全回路 红/黄（项目标准优先）；
  - 普通信号 灰/白；模拟量按屏蔽/对绞要求，颜色随项目。
- 颜色只是标识，不替代线号；项目有颜色标准时以项目为准。

### 6.6 校验

- `TERM-ID`唯一；`端子号`排内唯一/连续；备用在排尾。
- 每个端子一行一根线；无一个端子两个`线号`。
- `线号`最多出现两次；两次必须互为`对接端子`；一次必须是设备/PLC端。
- `对接端子`格式合法且存在；`BRIDGE`只能指向同电位端子。
- 每个使用中IO有对应端子（或明确“无端子/现有设备”说明）；安全信号在X4。
- 每排备用≥15%；备用行不计入使用数。
- 导线截面与电缆表一致；颜色字段有值/`—`。
- 不出现端子排布图/接线图。

### 7.2 适用性

`适用性` 只允许 `适用`、`不适用`、`待确认`。

判断依据（确定性）：

- 条款关键词/专业类别 vs 项目事实：是否有24V控制、动力电缆、安全回路、PE、端子、PLC、防护/环境等。
- 项目有对应对象且条款主题匹配→`适用`；
- 明确不存在对应对象/阶段→`不适用`，并写理由；
- 关键词泛化、证据不足、需要风险评价/IP等级/接地实测→`待确认`。

不得用LLM“感觉”判适用；不得把库里的历史项目适用性直接照搬；如库有`本项目适用性`，只作提示，必须按本项目事实复核并记录。

### 7.3 设计证据

`设计证据` 必须能定位到实际文件/行/ID：

```text
loop_description.md §W3；cable_schedule.xlsx W3-C01；terminal_list.xlsx X4-01～X4-04；BOM-010/011/012；io_address.xlsx IO-001
```

禁止写“已考虑”“满足要求”“按规范”这种无证据文案；无证据→`待人工判定`，不得判`满足`。

### 7.4 初步判定

`初步判定` 只允许 `满足`、`不满足`、`待人工判定`、`不适用`。

- `满足`：有可核对证据，且按条款判定规则技术核对通过；
- `不满足`：有证据表明违反明确规则；
- `待人工判定`：证据不足、需风险评价/实测/标准解释；
- `不适用`：对象不存在，写明理由。

**重要**：`满足` 仅表示“按本项目证据和判定规则的技术预检满足”，不表示合规认证/法律结论；`初步判定` 是技术预检，最终由工程师确认。`00-说明` 必须写这句。

### 7.5 整改循环

- 对 `不满足` 且规则明确的项：在JSON模型上整改（改回路/电缆/BOM/端子/地址），重算、重导出、重判；记录`remediation_log`（前后值、理由、影响ID、轮次）。
- 对 `待人工判定`：不得自动改成`满足`；列入`open_items`，等工程师给证据/裁决。
- 对 `不适用`：保留理由；不得为了“全绿”改成适用。
- 整改只能选库内器件/电缆数据；不得编型号/参数/证据。
- 最多5轮；仍不收敛→停止，保留`不满足`/`待人工判定`，报告阻塞。

**模拟模式（仅 `auto_simulate_customer=true`）**：

- `待人工判定` 项允许由模拟安全评估给出**预判**，但 `初步判定` 列**保持 `待人工判定` 原值不动**；预判结论写进 `整改建议` 列，前缀 `【模拟裁决】`，格式：`【模拟裁决】预判满足/预判不满足；依据…；需人工复核…`。
- 报告与 `open_items` 必须逐条列出这些项；不得把预判写成 `满足`，不得声称“强条已通过”。
- `不满足` 项不适用本分支：仍必须整改或保留 `不满足`。
- 上游编排层（auto-flow-master-00 §G3-04）在模拟模式下据此判 `通过（模拟）`，不阻塞；`auto_simulate_customer=false` 时行为不变。
- 最终表可以没有`不满足`（若整改完成），但可以有`待人工判定`；不得声称“全部合规”。

### 7.6 输出字段（7列，顺序固定）

```text
CLAUSE-ID | 标准编号 | 条款摘要 | 适用性 | 设计证据 | 初步判定 | 整改建议
```

- 只允许这7列；标准名称/风险等级/条款号等放`00-说明`或JSON，不塞进主表。
- `条款摘要` 用库内标题/原文节选，不改写法律含义；不得编条款号。
- `整改建议`：`不满足`/`待人工判定`给具体动作；`满足`/`不适用`写`—`。
- 主表`01-强条自检`；`00-说明与版本`；`02-整改记录`（可选）。

### 7.7 一票否决

- 库字段`一票否决=是`且`初步判定=不满足`：最高优先级，必须整改或阻塞；不得带病交付。
- `待人工判定` 的一票否决项也必须列在`open_items`，不得隐藏。

## 8. drawing_data.json 统一数据源

### 8.1 定位

步骤3-6的“再次读取前面文件汇总”在实现上等价于：先把各步骤结果汇总到统一模型，写 `drawing_data.json`，再由JSON重放所有xlsx/md。不要先定稿表格再补JSON，否则会产生双源。

`drawing_data.json` 是唯一权威源：

- 所有xlsx/md从JSON导出；
- 改数据只改JSON（或改生成JSON的模型脚本），再运行导出；
- 任何xlsx/md手工修改都不算数；重新导出会覆盖；
- JSON带`data_version`、`address_version`、`export_manifest`（文件哈希）。

### 8.2 顶层结构

JSON使用UTF-8、缩进2空格、无注释；所有ID与xlsx一致。

```json
{
  "schema_version": "3.0",
  "kind": "electrical-construction-ssot",
  "project": {"id": "...", "name": "...", "stage": "S3"},
  "data_version": "DATA-V1.0",
  "address_version": "ADDR-V1.0",
  "generated_at": "YYYY-MM-DDTHH:MM:SS",
  "authority": {
    "source_of_truth": "drawing_data.json",
    "export_rule": "所有xlsx/md从本JSON导出；禁止只改表格",
    "conflict_rule": "文件与JSON不一致时，以JSON为准并重导出"
  },
  "address_profile": {"profile_id": "...", "note": "..."},
  "inputs": {"io_list": {"path": "...", "sha256": "..."}, "bom": {}, "clause_library": {}},
  "requirements": [],
  "io": [],
  "addresses": [],
  "bom": [],
  "loops": [],
  "cables": [],
  "terminals": [],
  "clauses": [],
  "checks": {},
  "traceability": {},
  "remediation_log": [],
  "version_log": [],
  "open_items": [],
  "export_manifest": [],
  "stats": {}
}
```

### 8.3 必备内容

| 键 | 内容 |
|---|---|
| `requirements` | REQ-ID、内容摘要、状态；无阶段1文件时只放引用ID并标`referenced-only` |
| `io` | IO-ID、信号、类型、设备标签、REQ、BOM、回路 |
| `addresses` | IO-ID、物理地址、地址区、版本、profile |
| `bom` | BOM-ID、类别、型号、数量、供应商、回路、IO |
| `loops` | W编号、类型、功能、器件、保护、电缆、端子、REQ |
| `cables` | 全部输入/结果/判定/数据来源 |
| `terminals` | 8字段+回路/条排追溯 |
| `clauses` | 7字段+库内标准名称/风险/一票否决/证据类型 |
| `checks` | 地址/电缆/端子/强条/JSON同步汇总 |
| `traceability` | req→io→address→loop→cable→terminal→clause |
| `remediation_log` | 每轮整改前后、理由、影响ID |
| `version_log` | ADDR/DATA版本变化 |
| `open_items` | 待补数据、待人工判定、缺件、假设 |
| `export_manifest` | 文件名、sha256、data_version、exported_at |
| `stats` | 计数/通过率/待办数 |

### 8.4 导出与校验

1. 生成/更新JSON；
2. 从JSON导出5个附属文件；
3. 计算每个文件SHA256，写入`export_manifest`；
4. 文件`说明`记录`DATA-V`和最终JSON文件的SHA256；JSON自身不写自己的哈希，避免自引用；
5. 重新读取xlsx/md，核对：
   - 行数/ID集合/关键字段与JSON一致；
   - 文件`说明`中的DATA-V/JSON指纹一致；
   - 无JSON中不存在的ID；
6. 不一致→停止，重导出；不得手工修补表格。

### 8.5 版本

- 地址变化→`ADDR-V`升版+`DATA-V`升版；
- 电缆/端子/强条/回路变化→`DATA-V`升版；
- `version_log`记录原因/影响；
- 旧版JSON保留在`versions/`或归档；至少保留变更日志。

### 8.6 说明

- JSON是结构化绘图数据，不是图纸；EPLAN/CAD图面布局/排版仍需工程师人工调整。
- 不输出图形坐标/图框/图层；只输出可被下游读取的实体/关系/参数。

## 9. 一致性与整改循环

### 9.1 必检一致性

| 检查 | 要求 |
|---|---|
| IO↔地址 | 每个使用中物理IO唯一地址；备用在末尾；无重叠 |
| IO↔回路 | 每个使用中IO有回路；每个回路有REQ/器件 |
| 回路↔电缆 | 电缆前缀=回路号；每条电缆有起终点/截面/长度 |
| 电缆↔端子 | 线号/截面/回路一致；端子`PLC:`地址存在 |
| 端子一线一端子 | 每端子一行一根线；无两端冲突；15%备用 |
| 强条↔证据 | 每条证据可定位；无编造条款/证据 |
| JSON↔导出 | ID/行数/关键值/版本/哈希一致 |

### 9.2 整改

- 只改JSON模型；改后重算/重导出/重校验。
- 地址改→升ADDR-V；电缆/端子/强条改→升DATA-V。
- 需要改BOM时，只能从阶段2器件库/BOM已有型号或库内合格项选择；新增/替换型号必须能在库内回查，旧BOM-ID保留追溯，不得编型号。
- 不通过项只允许用库内型号/数据整改；无库内项→阻塞。
- 不伪造证据；`待人工判定`不自动关闭。
- 最多5轮；记录`remediation_log`；未收敛→报告。

## 附录 Z：实机回归失败模式与强制检查

> 来源：2026-11-16 首次端到端真实执行（81 条用例在 PLCSIM 上跑，项目与设备信息已脱敏）暴露的问题反推。本技能此前缺该附录，与 01/02/04/05/06 对齐后补齐。编号 `EL-` 前缀唯一，交付前逐条打勾。

### Z.1 端子表必须带 `IO-ID`（EL-01 · 强制）

端子表若只有 `信号名称`、没有 `IO-ID`，阶段5 只能靠中文名做字符串匹配构建 IO→TERM 链，链路完整率永远到不了 100%。

- 硬规则：`terminal_list.xlsx` 与 `drawing_data.json.terminals[]` 的每个连接类端子必须有 `io_id` 与 `loop_id`；
- 备用端子填 `—`，但不得因"备用"而省略该列；
- 校验：`terminals[]` 中 `io_id` 去重后应等于"使用中的物理 IO 集合"（多对一允许，一对多不允许）。

### Z.2 NC/NO 语义必须逐点落表（EL-02 · 强制）

阶段4 的取反逻辑完全依赖 `NC语义` 列。缺列或写"待确认"，阶段4 只能猜，实测会导致急停/安全门判据反向（正常时判为故障、故障时判为正常）。

- 开关量必须写 `NO`/`NC`；模拟量/内部/HMI 写 `—`；
- 语义来源只能是器件手册/原理图，不得按信号名猜（"急停"不等于一定 NC）。

### Z.3 符号必须与 PLC 变量表同源（EL-03 · 强制）

地址表写了符号、PLC 变量表却没有同名符号，程序下载后表现为"编译通过但读写的是空地址"。

- `plc_tag_map.csv`/`plc_tag_table.xml` 与 `io_address.xlsx` 的 `PLC符号` 必须逐字一致（脚本比对，不靠眼）；
- 由本阶段统一生成符号，阶段4 禁止再改名或另建 `SIG_IO_xxx` 兜底。

### Z.4 备用率用未舍入值判定（EL-04 · 强制）

`spare/total ≥ 15%` 必须用原始整数计算，不得先四舍五入到百分数再比（14.96% 舍入成 15.0% 会误判通过）。

- 判据：`spare_min = ceil(used/0.85) - used`，实际备用行数 ≥ `spare_min`；
- 每排单独判定，不合并各排凑比例。
