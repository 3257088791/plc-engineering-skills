# 分阶段输出目录改造方案（v2.0）

- 版本：v2.0（方案稿）
- 日期：2026-11-22
- 适用对象：auto-flow-master-00 及 req-spec-01、scheme-io-bom-02、elec-construction-03、plc-scl-gen-04、sim-trace-05、eval-archive-06
- 目标：把当前平铺在 `output/` 下的各阶段交付物，改为“每个阶段一个固定子目录”；跨阶段输入输出、状态文件、脚本、归档、文档同步调整。
- 性质：**破坏性路径变更**。建议在新工作区按本方案实施，旧项目通过迁移脚本过渡。
- 实施状态：已于 2026-11-22 在当前工作区落地 v2.0；`stage_paths.py` 与 `migrate_output_layout.py` 尚未落地。

---

## 0. 结论先行

推荐采用 **ASCII 数字前缀目录**，每个阶段一个目录：

```text
output/
├── 00-flow/
├── 01-requirements/
├── 02-scheme-io-bom/
├── 03-electrical/
├── 04-scl/
├── 05-sim-trace/
└── 06-eval-archive/
```

三条硬规则：

1. `output/` 根目录**只允许**出现上述 7 个阶段目录（以及可选的 `README.md`），不得再出现任何交付物文件。
2. 每个交付物只允许放在自己的阶段目录；跨阶段读取只读上游目录，不得复制到下游目录。
3. 路径名、阶段目录名、文件名必须集中到一个 `stage_paths.py` 常量模块，禁止在 7 份技能里各自写死。

采用 ASCII 的理由：Windows/Linux/macOS 路径一致、shell/CI/zip 不涉及全角字符、JSON 清单可用 POSIX 分隔符稳定哈希。中文名称只用于文档展示。

如果坚持中文目录名，只需改 `stage_paths.py` 的 `STAGE_DIRS`，其余代码不动；但不建议在 v2.0 同时支持两套中文名。

## 1. 目标与非目标

### 1.1 目标

- 每个阶段的交付物、过程证据、脚本都在自己的阶段目录内。
- 阶段目录名固定、可排序、可脚本校验。
- `flow_status.json`、`flow_shturl`、`drawing_data.json`、`eval_data.json` 中的所有路径同步更新。
- 现有 17 项交付物数量不变，只改变位置。
- 支持旧项目一次性迁移，迁移可 dry-run、可回滚。
- 归档目录与阶段目录一一对应，便于复核。

### 1.2 非目标

- 不改变各阶段业务规则、字段、表头、判定逻辑。
- 不改变 17 项交付物清单和 14 项指标。
- 不把 `archive/` 移进 `output/`；归档仍是项目根目录下的最终打包区。
- 不引入数据库、对象存储或新的运行时依赖。
- 不在本方案中实现“阶段3.5 TIA 工程准备”等业务增强；只做目录改造。

### 2.2 目录名与显示名

| 阶段 | 目录名（推荐） | 文档显示名 |
|---|---|---|
| 0 | `00-flow` | 流程控制 |
| 1 | `01-requirements` | 需求澄清与规格 |
| 2 | `02-scheme-io-bom` | 控制方案、IO 与 BOM |
| 3 | `03-electrical` | 电气施工设计 |
| 4 | `04-scl` | SCL 程序 |
| 5 | `05-sim-trace` | 仿真验证与追溯 |
| 6 | `06-eval-archive` | 评估与归档 |

命名约束：

- 必须以两位阶段号开头，保证字典序等于流程顺序。
- 只使用小写 ASCII 字母、数字、短横线；不使用空格、下划线、中文、点号。
- 阶段目录名一经发布不得改名；改名属于新的 `layout_version`。
- 文件名保持现有名称，不在本次改造中重命名。

### 2.3 根目录约束

`output/` 根目录允许的条目：

```text
00-flow/
01-requirements/
02-scheme-io-bom/
03-electrical/
04-scl/
05-sim-trace/
06-eval-archive/
README.md（可选）
```

禁止：

- 根目录出现 `requirements_spec.xlsx`、`scheme.md`、`io_list.xlsx` 等散落交付物。
- 根目录出现 `_stage0/`、`_stage5/`、`_stage6/` 旧目录。
- 同一个交付物同时存在于旧平铺路径和新阶段路径。
- 在阶段目录内再建“阶段子目录”（例如 `03-electrical/03-electrical/`）。

### 2.4 阶段目录生命周期

- 阶段0：只创建 `output/00-flow/`，写入 `flow_status.json`、`flow_shturl`、`capabilities.json`。
- 阶段1 至 6：进入阶段时创建自己的阶段目录；不得提前创建空目录。
- 过程证据放本阶段 `_work/`；`_work/` 不进入 17 项交付物，不进入归档（除非显式 `--include-work`）。
- 阶段失败时保留本阶段目录，不删除、不改名、不清空。

## 4. 路径解析与单一常量

### 4.1 `stage_paths.py` 建议实现

放在技能公共资源目录，例如 `assets/common/stage_paths.py`，由 00～06 与所有校验脚本共同引用。

```python
from pathlib import Path

OUTPUT_ROOT = Path("./output")

STAGE_DIRS = {
    0: "00-flow",
    1: "01-requirements",
    2: "02-scheme-io-bom",
    3: "03-electrical",
    4: "04-scl",
    5: "05-sim-trace",
    6: "06-eval-archive",
}

STAGE_NAMES = {
    0: "流程控制",
    1: "需求澄清与规格",
    2: "控制方案、IO 与 BOM",
    3: "电气施工设计",
    4: "SCL 程序",
    5: "仿真验证与追溯",
    6: "评估与归档",
}

def stage_dir(stage: int) -> Path:
    if stage not in STAGE_DIRS:
        raise ValueError(f"invalid stage: {stage}")
    return OUTPUT_ROOT / STAGE_DIRS[stage]

def ensure_stage_dir(stage: int) -> Path:
    p = stage_dir(stage)
    p.mkdir(parents=True, exist_ok=True)
    return p

def out(stage: int, *parts: str) -> Path:
    return stage_dir(stage).joinpath(*parts)

def rel(stage: int, *parts: str) -> str:
    return "/".join([OUTPUT_ROOT.as_posix(), STAGE_DIRS[stage], *parts])

def safe_rel(path: str) -> str:
    p = Path(path)
    if p.is_absolute() or ".." in p.parts:
        raise ValueError(f"unsafe relative path: {path}")
    return p.as_posix()

def assert_within_output(path: Path) -> None:
    resolved = path.resolve()
    root = OUTPUT_ROOT.resolve()
    if root not in resolved.parents and resolved != root:
        raise ValueError(f"path escapes output/: {path}")
```

要求：

- 所有文件系统操作使用 `Path`，不手工拼 `\` 或 `/`。
- 所有写入 `flow_status.json`、`drawing_data.json`、`eval_data.json` 的路径使用 `rel()` 生成 POSIX 字符串。
- 所有读路径先 `safe_rel()`，再 `assert_within_output()`。
- 禁止绝对路径进入状态文件、清单、报告。

## 6. 门禁与错误码

### 6.1 新增布局门禁

建议在阶段0 与每个阶段输出门禁中增加：

| 门禁 | 检查 | 失败处理 |
|---|---|---|
| `G0-LAYOUT-01` | `output/` 只含允许的阶段目录（+可选 README.md） | `E00_LAYOUT_INVALID` |
| `G0-LAYOUT-02` | `00-flow/flow_status.json`、`flow_shturl` 可读写 | `E00_PREFLIGHT` |
| `G0-LAYOUT-03` | `flow_status.layout_version == "2.0"` | `E00_LAYOUT_VERSION` |
| `G0-LAYOUT-04` | 不存在旧平铺交付物 | `E00_LAYOUT_CONFLICT` |
| `Gx-PATH-01` | 本阶段所有输出都在本阶段目录 | `E00_LAYOUT_INVALID` |
| `Gx-PATH-02` | 跨阶段输入解析到上游阶段目录 | `E00_LAYOUT_INVALID` |
| `Gx-PATH-03` | 同一文件不在两个阶段目录重复 | `E00_LAYOUT_CONFLICT` |
| `Gx-PATH-04` | 状态/清单中的路径均为安全相对路径 | `E00_PATH_UNSAFE` |
| `G6-ARCHIVE-01` | 归档目录与阶段目录一一对应 | `E15_ARCHIVE_INCOMPLETE` |

### 6.2 新增错误码

当前 65 个错误码，建议增加 4 个，变为 69 个：

| 错误码 | 阶段 | 条件 | 顶层状态 |
|---|---|---|---|
| `E00_LAYOUT_INVALID` | 0/任意 | `output/` 根目录有散落文件、阶段目录缺失或命名错误、文件放错阶段 | `failed` |
| `E00_LAYOUT_CONFLICT` | 0/任意 | 旧平铺文件与新阶段文件同时存在，或同一交付物出现在两个阶段目录 | `failed` |
| `E00_LAYOUT_VERSION` | 0/续跑 | `flow_status.layout_version` 不是 `2.0`，未迁移 | `blocked` |
| `E00_PATH_UNSAFE` | 任意 | 状态/清单/报告中出现绝对路径或 `..` | `failed` |

错误对象示例：

```json
{
  "code": "E00_LAYOUT_CONFLICT",
  "stage": 0,
  "message": "检测到旧平铺交付物与新阶段交付物同时存在：output/requirements_spec.xlsx 与 output/01-requirements/requirements_spec.xlsx",
  "evidence": ["output/requirements_spec.xlsx", "output/01-requirements/requirements_spec.xlsx"],
  "next_action": "运行 tools/migrate_output_layout.py --dry-run，确认后迁移；不要手工删除旧文件",
  "artifacts": [],
  "resume": {"resumable": true, "from_stage": 0, "reason": "layout migration"}
}
```

### 6.3 `fresh` / `resume` 行为

- `fresh`：先检查旧平铺文件；存在则 `E00_LAYOUT_CONFLICT`，要求先迁移，不自动删除。
- `resume`：读 `layout_version`；不是 `2.0` → `E00_LAYOUT_VERSION`，要求迁移。
- `resume`：校验已成功阶段的 `outputs` 都在新阶段目录；不在则 `E00_LAYOUT_INVALID`。
- 迁移后 `flow_status.json` 的 `baseline`/`artifacts` 必须重算哈希，不能直接沿用旧键。

## 7. 兼容与迁移

### 7.1 版本策略

建议 **v2.0 硬切**：

- 新工作区直接使用新布局。
- 旧项目必须运行迁移脚本；不提供长期双布局支持。
- `flow_status.layout_version` 作为唯一判据。
- v1.1 保留为历史版本，不再接收路径修复。

不建议长期同时支持平铺和分阶段两套路径：双布局会让门禁、哈希、归档、文档全部翻倍，最终一定漂移。

### 7.2 迁移脚本 `tools/migrate_output_layout.py`

CLI：

```text
python tools/migrate_output_layout.py --project . --dry-run
python tools/migrate_output_layout.py --project . --apply
python tools/migrate_output_layout.py --project . --apply --delete-old
python tools/migrate_output_layout.py --project . --apply --force
```

默认 `--dry-run`，只打印计划，不改文件。

执行步骤：

1. 检测当前布局：`flat_v1`、`staged_v2`、`mixed`、`empty`。
2. 若 `mixed` 且未 `--force`：退出码 1，列冲突文件。
3. 创建 7 个阶段目录（只创建需要的）。
4. 按映射表复制文件；默认复制，不移动。
5. 复制后校验 SHA256 与源文件一致。
6. 更新 `flow_status.json`：
   - `schema_version` → `2.0`
   - `layout_version` → `2.0`
   - `output_layout` → `staged`
   - `output_root` → `./output`
   - `stage_dirs` 写入
   - `inputs`/`outputs`/`baseline`/`artifacts` 路径按映射替换
   - 重算已存在文件的哈希
7. 移动/复制 `flow_shturl` 到 `00-flow/`，追加：
   ```text
   [时间] [FLOW] [MIGRATE] 从 flat_v1 迁移到 staged_v2 | moved=17 skipped=0 conflicts=0
   ```
8. 写 `00-flow/migration_report.md`：旧路径、新路径、哈希、结果。
9. `--delete-old` 时，确认新文件哈希一致后删除旧平铺文件；默认不删。
10. 退出码：`0` 成功，`1` 冲突/失败，`2` 输入缺失。

迁移脚本约束：

- 不迁移 `archive/`；归档另行重建。
- 不覆盖已存在的新路径文件，除非 `--force`。
- 不删除 `_stage5`/`_stage6`，除非 `--delete-old` 且新 `_work` 已校验。
- 不修改 `flow_shturl` 历史内容，只追加 `MIGRATE`。
- 迁移前后都计算文件哈希，报告可复核。
- 幂等：重复执行 `--apply` 不产生重复文件、不重复追加日志（用 `migration_id` 去重）。

### 7.3 迁移后的归档

迁移只改 `output/`，不自动重建 `archive/`。迁移完成后：

1. 运行阶段6 的 `stage6_collect.py` / `stage6_render.py`，重新生成 `eval_data.json`、指标表、归档清单。
2. 按新 `project_archive_list.md` 重新打包到 `archive/<project_id>/`。
3. 旧 `archive/` 保留为历史快照，不覆盖；新归档使用新目录名。

## 附录 C：迁移脚本伪代码

```python
from pathlib import Path
import hashlib, json, shutil

MAPPING = [
    ("output/flow_status.json", "output/00-flow/flow_status.json"),
    ("output/flow_shturl", "output/00-flow/flow_shturl"),
    ("output/_stage0/capabilities.json", "output/00-flow/capabilities.json"),
    # ... 按第 3 节完整映射
]

def migrate(project: Path, apply: bool, delete_old: bool, force: bool):
    plan = []
    for old, new in MAPPING:
        src = project / old
        dst = project / new
        if src.exists() and dst.exists() and not force:
            raise LayoutConflict(old, new)
        if src.exists():
            plan.append((src, dst))

    if not apply:
        print_plan(plan)
        return 0

    for src, dst in plan:
        dst.parent.mkdir(parents=True, exist_ok=True)
        shutil.copy2(src, dst)
        assert sha256(src) == sha256(dst)

    update_flow_status(project)
    append_migrate_log(project)
    write_migration_report(project, plan)

    if delete_old:
        for src, _ in plan:
            src.unlink()

    return 0
```

`update_flow_status` 要做：

- 递归遍历 `inputs`/`outputs`/`baseline`/`artifacts`/`error.evidence`/`error.artifacts`。
- 用旧→新映射替换路径字符串。
- 重算存在文件的大小/哈希/mtime。
- 写 `layout_version`、`output_layout`、`output_root`、`stage_dirs`。
- 原子写入。
